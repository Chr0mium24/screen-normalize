# 《方法精简版》证据闭环修订设计

日期：2026-07-19

## 目标

将 `doc/current/paper/manuscript/paper_zh_方法精简版.md` 修订为可作为最终提交候选的版本，消除“实验尚未完成”的草稿口吻，并确保每个完成性结论都能由仓库中的现有实验记录直接支持。

本次修订不虚构新实验结果。能够由已有记录闭环的内容改写为已完成结果；现有证据无法独立支持的内容收窄为适用范围，或作为不影响主要结论成立的扩展方向。

## 证据来源

1. 十片段总体、分类、逐片段及状态统计：
   `doc/archive/current_cleanup_2026-07-14/small_sample_proposal_border_metrics_2026-07-14.md`
2. 滚动片段消融及状态记录：
   `doc/current/paper/proposal_border_ablation_2026-07-14.md`
3. 当前方法实现：
   `screen_normalize/algorithms/proposal_demo.py`、`screen_normalize/algorithms/boundary.py`、`screen_normalize/experiments/runner.py`
4. 当前论文已有参考文献及经检索核实的边界、线特征和平面跟踪相关工作。

## 修订范围

### 1. 状态统计闭环

- 删除“后续增加逐片段状态表”的句子。
- 在片段级结果中加入十个评价片段的正式状态统计表。
- 表格报告总帧数、普通边框接受、边框接受但 LK 冲突、保持上一帧等状态。
- 根据现有记录给出完整结论：十个片段均未发生保持上一帧；弱边框片段分别记录 36 和 45 帧 LK 冲突；挑战片段各记录 4 帧 LK 冲突。
- 明确这些统计证明当前评价片段中的低轨迹变化不是由保持旧四边形造成，同时不把“零保持”外推到未评价视频。

### 2. 草稿口吻清理

- 全文检索并处理“后续版本还应”“当前正文先”“后续可以”“仍需要”“将进一步验证”“使评价更加完整”等表述。
- 对仓库已有结果能够回答的问题，补入结果并改写为完成时态。
- 对没有独立实验支撑的问题，删除完成性承诺，改成当前方法的明确适用范围或结论边界。
- 讨论部分保留必要限制，但不再把完成主要论证所需的实验列为未来任务。
- 结论只陈述十个评价片段和现有消融能够支持的结果，不使用暗示论文仍待完成的结尾。

### 3. 数据与评价协议表述

- 删除“后续版本还应补充”的编辑备注。
- 将已知协议写成确定表述：50 个视频构成项目数据集，定量评价使用每类两个、共十个标注片段；主结果是该固定评价子集上的片段级汇总。
- 未在现有材料中记录的设备、选择程序或调参细节不伪造；通过限制结论适用范围，避免把十片段结果表述为全部 50 个视频的总体估计。

### 4. 相关工作与新颖性定位

- 按四条技术路线组织相关工作：平面矫正与单应模型、特征点平面跟踪、线段/边界几何、视频轨迹平滑。
- 明确 LK、Shi-Tomasi、RANSAC、LSD、Hough 和单应变换均为经典组件，不将其表述为本文原创。
- 将本文的新颖性限定为面向拍屏视频双运动源问题的证据组织方式：物理屏幕边框决定几何，内部纹理运动只用于一致性诊断。
- 避免未经系统综述支持的绝对表述，例如“现有方法均未解决”；改为说明现有路线在屏幕内部内容独立运动时为何不能直接保证物理边框对齐。
- 新增文献前先核实题名、作者、出版信息及其与具体论述的对应关系。

### 5. 消融与限制表述

- 将单片段消融明确定位为机制验证，不外推为跨场景统计结论。
- 使用已有状态记录说明该滚动片段中边框每帧均被接受，因此重检测与保持回退没有触发；这解释对应变体结果不变，而不是把它写成尚未完成。
- LK 关闭后几何结果不变，用于证明 LK 不主导单应矩阵；不宣称现有实验已经测得冲突分类准确率。
- 对密集时间真值、跨设备泛化等内容，仅作为研究范围边界或可选扩展，不写成支撑当前主要结论所必需的缺失工作。

## 修改记录文档

实施完成后，在同一目录新增修订记录，至少包含：

| 字段 | 内容 |
|---|---|
| 原位置 | 原章节或原句关键词 |
| 修改类型 | 删除、改写、补表、补充文献或结论收窄 |
| 修改后内容 | 修改后的核心表述 |
| 证据 | 对应实验记录、代码位置或参考文献 |
| 理由 | 消除草稿痕迹、补齐证据链或避免过度外推 |

## 验证标准

1. 正文不再包含暗示主要实验尚未完成的编辑备注。
2. 十片段状态统计与归档记录逐项一致。
3. 摘要、贡献、结果、讨论和结论中的主要主张均能映射到已有表格或消融。
4. 相关工作不宣称经典组件原创，也不使用无法由引用支撑的绝对新颖性判断。
5. 不将单片段消融或十片段评价外推为全部设备、全部场景或全部 50 个视频的统计结论。
6. 使用关键词扫描检查 `后续版本`、`当前正文先`、`后续可以`、`仍需要`、`待补`、`TBD` 和 `TODO`。
7. 修改后的论文和修订记录分别通过 `git diff --check`，并在同一实现提交中提交。

## 非目标

- 不重新运行全部 50 个视频的定量实验。
- 不生成不存在的设备信息、标注协议或参数选择记录。
- 不把 LK 冲突诊断包装成已经验证准确率的分类器。
- 不修改与本次论文证据闭环无关的代码和文档。
