# 信号保留诊断实现计划

日期：2026-07-19

## 目标

实现一个用于验证真实追踪管线是否保留拍屏摩尔纹频域结构的诊断算法。该算法不重新定义主几何指标，也不替代角点 RMSE、IoU 和轨迹变化；它只回答一个问题：经过目标裁剪、缩放、旋转、透视矫正和图像稳定后，原始拍屏摩尔纹的主频、方向、能量和峰形是否发生可解释的改变。

## 核心输入

每一帧的诊断输入为三元组：

```text
(R_t_raw, R_t_track, T_t)
```

| 输入 | 含义 | 来源 |
|---|---|---|
| `R_t_raw` | 原始视频帧中的对应目标区域 | 从原始帧按目标四边形或目标框裁出 |
| `R_t_track` | 真实追踪管线输出的目标图像 | 使用项目当前输出，不额外关闭裁剪、缩放、旋转、透视矫正或稳定 |
| `T_t` | 原始区域到追踪输出之间的几何变换 | 目标框、四边形、缩放比例、旋转角、仿射矩阵或透视矩阵 |

关键约束：诊断必须使用真实追踪输出，不能为了简化实验单独去掉裁剪、缩放、旋转、透视矫正或稳定，否则无法测到真实管线对摩尔纹频谱的影响。

## 数据采集设计

建议采集同一个带明显摩尔纹的屏幕目标，在下列运动状态下拍摄：

| 场景 | 目的 |
|---|---|
| 目标静止、相机静止 | 建立频谱峰稳定基线 |
| 目标平移 | 验证平移对频谱峰位置的影响应较小 |
| 目标旋转 | 验证频谱方向随旋转角可预测变化 |
| 目标远近变化 | 验证缩放导致主频半径变化 |
| 相机轻微抖动 | 验证稳定流程是否引入新峰或峰宽扩大 |
| 目标发生透视变化 | 验证透视矫正后频谱补偿是否仍可解释 |

每帧保存：

```text
frame_0001_raw.png
frame_0001_tracked.png
frame_0001_transform.json
```

`transform.json` 至少记录：

```json
{
  "frame_index": 1,
  "timestamp_sec": 0.033,
  "raw_region_corners": [[120, 80], [900, 95], [890, 620], [115, 610]],
  "tracked_size": [1920, 1080],
  "homography_raw_to_track": [
    [1.10, -0.08, 25.0],
    [0.08, 1.10, 14.0],
    [0.0001, 0.0002, 1.0]
  ],
  "scale": 1.12,
  "rotation_deg": 4.3
}
```

如果某些字段无法直接从现有管线获得，优先保存完整单应矩阵 `homography_raw_to_track`，再从矩阵中估计局部尺度和方向变化。

## 算法流程

1. 读取 `R_t_raw`、`R_t_track` 和 `T_t`。
2. 将两个图像转为灰度，并使用相同的窗口函数降低边界截断造成的频谱泄漏。
3. 分别计算二维 FFT 幅值谱，并转为对数幅值以压缩动态范围。
4. 在原始区域频谱中检测摩尔纹主峰，记录主频半径、方向、峰值能量和峰宽。
5. 根据 `T_t` 预测主峰在追踪输出频谱中的理论位置：
   - 平移不改变频率位置；
   - 图像旋转会使频谱方向同步旋转；
   - 图像缩放会使频率半径按反比例变化；
   - 透视矩阵使用目标区域中心或网格点估计局部仿射近似。
6. 在追踪输出频谱中检测对应主峰。
7. 对齐理论峰位置后，计算主频误差、方向误差、摩尔纹能量变化、峰宽变化和新峰数量。
8. 按帧输出 JSON，并按片段汇总中位数、四分位区间和异常帧比例。

## 输出指标

| 指标 | 定义 | 解释 |
|---|---|---|
| 主频误差 | 追踪输出峰半径与理论半径的相对误差 | 衡量缩放/透视补偿后频率位置是否保持 |
| 方向误差 | 追踪输出峰方向与理论方向的角度差 | 衡量旋转补偿后条纹方向是否保持 |
| 摩尔纹能量变化 | 对应峰局部能量的 dB 差值 | 衡量管线是否削弱或放大摩尔纹 |
| 峰宽变化 | 峰半高宽或局部二阶矩变化 | 衡量稳定和重采样是否使频谱变散 |
| 新峰数量 | 除理论对应峰以外的显著峰数量 | 衡量管线是否引入新的周期伪影 |

单帧输出示例：

```text
main_frequency_error: 2.1%
direction_error_deg: 1.4
moire_energy_delta_db: -0.5
peak_width_delta_percent: 6.2%
new_peak_count: 0
```

## 实现拆分

| 模块 | 文件建议 | 职责 |
|---|---|---|
| 数据导出 | `scripts/diagnostics/export_signal_diagnostic_inputs.py` | 从原始视频和追踪结果导出 raw、tracked、transform |
| 频谱分析 | `screen_normalize/diagnostics/signal_preservation.py` | FFT、峰检测、几何补偿和指标计算 |
| 批处理入口 | `scripts/diagnostics/run_signal_preservation_diagnostic.py` | 批量读取导出帧，生成逐帧和片段汇总 |
| 报告生成 | `scripts/paper/build_signal_preservation_figure.py` | 生成论文图 6 和汇总表 |

文件实现时应保持单文件少于 500 行；公共频谱函数放在 `screen_normalize/diagnostics/`，脚本只保留参数解析和 IO。

## 验证标准

1. 静止场景中主频误差和方向误差应接近 0，作为基础 sanity check。
2. 人工旋转测试中，方向补偿前应出现接近旋转角的变化，补偿后方向误差应明显减小。
3. 人工缩放测试中，主频半径应按缩放反比移动，补偿后主频误差应明显减小。
4. 同一帧输入重复运行应产生相同 JSON 指标。
5. 输出报告必须同时包含原始频谱峰、预测峰位置和追踪输出峰，便于人工检查错误来源。
